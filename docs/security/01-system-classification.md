# 01. Классификация системы

## Назначение системы

`Second Shelf` представляет собой multi-module Spring Boot backend для обмена книгами между пользователями.
Система реализована как набор из gateway и пяти domain services:

- `api-gateway`
- `auth-service`
- `user-service`
- `book-service`
- `exchange-service`
- `notification-service`

`api-gateway` является рекомендуемой frontend и production entry point. Каждый domain service использует
собственную PostgreSQL БД. Для асинхронной доставки доменных событий между
`exchange-service` и `notification-service` применяется RabbitMQ.

## Границы классифицируемой системы

В состав прикладной системы входят:

- публичный HTTP entry point через `api-gateway` и HTTP API domain services;
- внутренние service-to-service API, защищенные `X-Internal-Token`;
- базы данных `auth_db`, `users_db`, `books_db`, `exchange_db`, `notification_db`;
- RabbitMQ exchange, queue и DLQ, используемые для доставки событий обмена;
- конфигурация безопасности приложения: JWT, refresh-токены, правила авторизации, health checks.

В состав эксплуатационного контура, но вне runtime-кода приложения, входят:

- внешний reverse proxy или ingress перед `api-gateway`;
- TLS-терминация;
- firewall и сегментация сети;
- централизованное логирование и мониторинг;
- secret manager;
- backup storage;
- IDS/IPS, DNS-логирование, EDR/антивирус, синхронизация времени.

## Обрабатываемая информация

Система обрабатывает обычные персональные данные пользователей:

- `username`
- `email`
- `firstName`
- `lastName`
- `city`
- `about`
- внутренние `userId`
- сообщения обмена книгами
- содержимое уведомлений

Дополнительно система обрабатывает аутентификационные данные:

- пароль пользователя в момент регистрации и логина;
- bcrypt-хэш пароля в `user-service`;
- JWT access token;
- refresh-токен и его SHA-256 хэш;
- внутренний сервисный токен `X-Internal-Token`.

## Основание для предварительной классификации

Для `Second Shelf` принимается предварительная классификация `3-ИН`, поскольку:

- система подключена к открытым каналам передачи данных;
- она обрабатывает обычные персональные данные пользователей;
- имеются публичные API и взаимодействие с внешними клиентами через сеть;
- нарушение конфиденциальности, целостности или доступности повлияет на права пользователей и бизнес-функции обмена.

## Вывод

На уровне проектной документации `Second Shelf` рассматривается как система класса `3-ИН` и подготовлена для
развертывания в attestation-ready environment.
При этом итоговая аттестация должна выполняться для конкретной среды развертывания, а не только для исходного кода:
на результат будут влиять выбранный хостинг в Республике Беларусь, схема сетевой изоляции, настройка TLS,
средства регистрации событий, резервного копирования и управления секретами.
